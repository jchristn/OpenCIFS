## Unreleased

- Added the release-readiness validation slice: `eng/OpenCIFS.Build` now validates `docs/interop-matrix.md` structure alongside the existing coverage-matrix and package-graph checks, `eng/validate-release-artifacts.ps1` now rejects stale concrete verification dates and missing pass-row evidence across the coverage and interop release artifacts, and `eng/run-release-gates.ps1` now reruns the full `Release` integration stack in one command before recording a summary in `artifacts/release-gates/release-gates.json`. The full Release gate, including Touchstone, framework runners, package smoke, README smoke, Python real-client, Samba, native Windows, and release-artifact validation, was rerun successfully after the change.
- Added the integration-readiness hardening slice: `eng/run-readme-smoke.ps1` now compiles a temporary downstream consumer from the documented client and server examples and verifies authenticated echo, directory create, file write or read, metadata query, enumeration, rename, cleanup, callback invocation, and non-empty-directory delete rejection; `eng/test.ps1` now includes both package-smoke and README-smoke coverage; `eng/run-integration-gates.ps1` now composes the clean build, Touchstone console suites, framework runner matrix, package smoke, README smoke, Python real-client, Samba, and native Windows interop smoke into one local gate; and the shared direct-TCP test helpers now reserve loopback ports through a named cross-process semaphore so the full multi-target matrix remains stable under parallel load. The combined integration gate was rerun successfully after the change.
- Hardened the feed-facing package slice: packable product and dependency libraries now emit package-specific readmes and richer package metadata, the package smoke harness now validates emitted nuspec metadata plus readme and XML-doc payloads before restoring the downstream consumer, and the README or roadmap documentation now reflects that verified package-consumer integration scope instead of the earlier generic repository readme packaging.
- Added the package-consumer integration slice: `OpenCIFS.Security` and `OpenCIFS.Transport` are now packable so the `OpenCIFS.Client` and `OpenCIFS.Server` package graph restores cleanly, `eng/OpenCIFS.Build` now validates that every packable project only references other packable projects, and `eng/run-package-smoke.ps1` now packs the product libraries into a local feed and verifies a generated downstream consumer can restore and run authenticated echo, directory create, file write or read, metadata query, enumeration, rename, cleanup, bad-credential rejection, and non-empty-directory delete rejection from packaged artifacts. The full build, Touchstone, and `eng/test.ps1` entrypoint were rerun after the change.
- Added the bounded SMB 2.1 large-I/O slice: `OpenCifsServerHost` now advertises `SMB2_GLOBAL_CAP_LARGE_MTU`, tracks negotiated max read or write sizes, accepts compatible overcharged multi-credit requests, and validates bounded large-I/O `CreditCharge` shapes; `OpenCifsClientSession`, `OpenCifsClientConnection`, and `OpenCifsClientFacade` now track negotiated large-I/O limits, grow the credit window through authenticated `ECHO`, build bounded multi-credit read or write requests, and chunk facade transfers when the peer credit window is smaller than the total payload. Shared client, server, and loopback coverage now exercises positive and negative large-I/O flows, and the direct-TCP client now accepts unsigned interim async `STATUS_PENDING` responses while still rejecting unsigned final async responses, matching the bounded Samba behavior surfaced during validation. The full build, Touchstone, `dotnet test`, Python real-client, Samba, and native Windows client smoke paths were rerun after the change, with verified `200000`-byte large-transfer evidence recorded in the real-client, Samba, and Windows interop artifacts.
- Added the bounded SMB 2.1 lease slice: `OpenCifsServerHost`, `OpenCifsClientSession`, and `OpenCifsClientConnection` now handle SMB 2.1 `RqLs` create contexts, read/write/handle lease grant tracking, signed lease-break notifications and acknowledgments, managed direct-TCP lease wait-and-ack handling, and rejection of same-lease-key path mismatches, invalid acknowledgments, and unexpected or unsigned notifications. Shared core, server, client, direct-TCP, and loopback coverage now exercises both positive and negative lease flows, and the full build, Touchstone, `dotnet test`, Python real-client, Samba, and native Windows client smoke paths were rerun after the change.
- Added the bounded SMB 2.1 lockstep slice: the managed client and server now negotiate and run the existing session, tree, file-I/O, metadata, notification, locking, oplock, and bounded durable-reconnect surface under SMB 2.1; the SMB1 multi-protocol bootstrap bridge now offers both `Smb2002` and `Smb21` and supplies the required non-empty SMB 2.1 client GUID; the Python `smbprotocol` harness now pins the correct SMB 2.1 dialect constant; and the full build, Touchstone, `dotnet test`, Python real-client, Samba, and native Windows client smoke paths were rerun under the verified SMB 2.1 scope.
- Added the bounded SMB 2.0.2 durable-lock carryover slice: detached durable opens now preserve byte-range lock state across abrupt transport disconnect, reconnect restores lock ownership to the re-established open, competing reads and lock requests stay rejected while the durable open is detached or reconnected, and shared server or client or loopback coverage now exercises positive unlock recovery plus negative detached and post-reconnect conflict paths. The full build, Touchstone, `dotnet test`, Python real-client, Samba, and native Windows client smoke paths were rerun after the change.
- Added explicit SMB2 status propagation on the managed client surface through `OpenCifsStatusException`, so low-level and high-level `OpenCIFS.Client` operations now preserve the failing SMB2 command and NTSTATUS instead of collapsing server-declared failures to generic operation errors. Shared client coverage now asserts exact statuses for session-setup failure, tree-connect failure, metadata failure, share-access conflict, lock conflict, and non-empty-directory delete rejection, and the Docker-backed Samba smoke now asserts the exact status-bearing client failures on its expected rejection paths. The full build, Touchstone, `dotnet test`, Samba, Python real-client, and native Windows client smoke paths were rerun after the change.
- Added the bounded SMB 2.0.2 durable-reconnect slice: SMB2 durable create and reconnect context codecs, shared persistent and volatile file IDs, detached durable-open tracking across abrupt transport disconnect, low-level client durable-open request and reconnect flows, and positive or negative core or server or client or loopback coverage for reconnect success, reconnect rejection, and nondurable-handle rejection. This slice also fixed native Windows compatibility by tolerating padded zero-length create contexts, adding `FILE_INTERNAL_INFORMATION` query support, preserving attribute-only read-only clearing across share-none without granting file-read data access, and accepting the bounded cancel-header shape seen during interop validation. - Added the bounded SMB 2.0.2 oplock-break slice: `OpenCifsClientSession`, `OpenCifsClientConnection`, and `OpenCifsServerHost` now handle signed exclusive `OPLOCK_BREAK` notifications and acknowledgments, the direct-TCP server shared-state path now correctly triggers breaks across connection-scoped hosts instead of accidentally suppressing them on colliding volatile file IDs, and shared core or server or client or loopback suites now cover positive and negative oplock codec, state, direct-TCP, and loopback flows.
